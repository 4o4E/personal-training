# Proposal

## Why

训练时反复输入重量和次数影响连续操作；所有动作的输入、计划和记录同时展开，难以辨认当前动作与完成进度。用户已确认采用数值框旁的小型拖动按钮与轻触反馈，以及按动作状态组织的紧凑训练页面。

## What Changes

- 次数和重量支持数值框旁的小型按钮按住拖动、加减按钮与手动输入；拖动须系统长按成功后才激活，长按成功时触觉一次，长按前的滑动交由页面滚动，激活后跨刻度继续使用原有轻触反馈；控件保持单行紧凑。
- 次数按整数调整；重量保留原始单位与小数，支持0.5、1、2.5、5、10的快捷步长并记住动作选择，保留常用重量入口。
- 动作名称只显示一次，移除力量训练标签，计划紧接动作标题并与实际记录分开。
- 保持原有连续进度条样式及实际完成组数；当前动作、已完成动作与其他未完成动作分别强调，默认只展开当前动作输入。
- 同一动作完成一组后保持当前动作，全部目标完成后突出下一个未完成动作；允许主动切换，并保持各组输入草稿。
- 休息计时紧凑展示，不重复动作标题；继续保留教学、实际结果修改、撤销、分段记录及训练反馈。

## Capabilities

### New Capabilities

无。

### Modified Capabilities

- `training-session-execution`：扩展训练数值输入、真实组进度、动作状态与计划和实际记录的展示要求；沿用已有变更中的同名能力，不建立另一套训练执行规范。

## Impact

- Android训练页面、当天完成页面、实际组编辑与本机交互偏好；使用现有Compose Foundation、Material3和系统触觉接口。
- 不改变训练资料、后端接口、数据库结构、重量单位、组保存与组间休息逻辑，不改变计划编辑及日历记录弹窗。
- 由GPT-6-Luna分别实现数值控件与训练页面，主助手负责集成、一加9R验收及正式签名生产APK交付。
