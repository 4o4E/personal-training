# Design

## Context

- 动作选择器可读取内置动作或网站目录；网站名称列表即使已缓存，首次选择仍向后端发 POST。仓库内已有生成目录、选择映射和教学资源的同一份来源。现有同步已经能上传本机新增的动作及依赖它的计划、训练。
- 训练卡片已有「更换剩余动作」和「订正实际动作 / 器械」，前者藏在折叠区。共享规则已能将零完成组的普通条目原位替换；有已完成组时保留历史并转移未完成部分。曾导入的来源条目标识受历史完整性约束。
- 组结果保存了实际完成时刻，但手动结束写点击时刻；目前只有准备新日期时才收起旧的进行中记录。健康接口按日期提供日概览及分页明细，本机缓存可以区分未下载与已知没有记录。

## Goals / Non-Goals

**Goals:** 保留本机优先写入、既有同步冲突语义和单日唯一记录；选项导出和备份不混用；无需数据库表结构或公开接口变更。

**Non-Goals:** 改写历史已完成记录、替换未来计划、全量离线下载教学媒体、发布或安装到正式手机。

## Decisions

### 用户已明确的行为

- 后端连不上只影响同步；添加动作不等后端。
- 训练中可换动作；在开始训练页直接看图，精简计划／器械与已完成状态，用图标显示备注编辑及组操作，用圆点标记进度分段。
- 导出支持日期范围、多选数据项目和 ZIP 分享。训练完成时间取最后实际训练时刻；半小时没有更新自动完成。

### 实施决定

用户回复「开始实施，可以用droidharbor认领机器做9r做测试」，确认以下方案并授权一加 9R 隔离验收。

1. **来源目录随 App 提供。** 从既有目录产物向 App 提供动作名称、选择映射和教学引用，使用与服务器一致的动作 ID、类型和映射；已保存动作优先复用，首次选择只在手机保存，走既有同步队列。仅缓存网站名称列表无法解决首次离线选择；另做一份目录会造成同一动作出现不同 ID，均不采用。已有内置或缓存图优先展示；公开图片按既有来源规则加载失败时，仅该图缺失。
2. **原位换练和事实订正分开。** 卡片直接提供换练入口。原动作没做过就从当前训练列表换掉；已做过保留实际组，新动作承接剩余目标，接着显示录入新动作的表单。保留历史来源引用，不把零完成组的遗留来源条目继续显示成待练动作。订正仍保留在次要菜单；不能以订正名义把真实做过的组算到另一个动作。
3. **同一个结束逻辑处理手动、到期和错过唤醒。** 半小时从最后一次实际训练状态更新算起，包括保存、修改或撤销完成组、调整当前训练内容、开始实际计时或明确续练；浏览或后台同步不刷新。记录活动时间用既有本机键值，不改表。应用运行时按期限结算；后台由系统调度，应用重启、返回前台及跨日时核对已过期记录。检查时重新读取状态和活动时间，避免旧回调关掉已续练的记录。无完成组不自动产生已完成记录，旧记录无真实组时间时不补造；结束同时停止本次计时。
4. **分享包和备份各走各的。** 分享包使用包内清单和按类别分开的文件；训练和结构化明细保留原始字段，日汇总保留 UTC+8 日期、真实值和单位。训练用手机已持久化记录（含未同步）；联网时按选择获取健康数据，离线或读取失败时明确标示可用的本机健康缓存和缺失日期／类别。只选训练时完全不访问健康接口。ZIP 中不放设置、token 或未选择的数据；通过 Android 文件保存或系统分享选择接收目标，生成文件前不声称成功。
5. **训练输入采用已确认的 B 版。** 当前动作左侧优先使用缓存或公开来源动图，右侧用统一的数字输入和上下箭头。点击单位只切换本组的原始单位，旁边的公斤等值只供阅读；无负重输入从 0 开始。已完成组继续保存原侧别和读数含义，主训练页不显示这些分类，也不改写历史。计时动作仍使用秒数和独立的开始计时操作。

## Risks / Trade-offs

- [同来源动作在两端各自添加] → 沿用同一 ID 与 JSON 语义，验证既有修订和同步冲突规则，不建重复动作。
- [系统限制后台唤醒] → 恢复时重查是否已过期限；即使后台晚执行，历史结束时间也不能写成唤醒时刻。
- [缓存不是完整历史] → 列明缺失、缓存和在线完整的范围，未下载不等于零；分页期间源版本改变时不能把混合版本标成完整。
- [换练与完成组表单已有草稿] → 用实际条目标识隔离草稿；原动作的重量不写入新动作。

## Migration Plan

覆盖升级继续读取原资料；现有已完成记录和个人数据不批量重写。升级时仍在进行中的记录按最后实际训练时刻核对到期。以隔离资料、既有后端契约和 Android 实机界面验收，验收后构建与核验正式签名 APK。
