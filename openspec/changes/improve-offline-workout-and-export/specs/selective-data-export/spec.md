# Spec Delta

## Purpose

让用户按日期和需要分享的数据项目生成资料 ZIP，不必发送整个备份。接收方能区分真实数据、确认为空的日期及尚未取得的数据。

## ADDED Requirements

### Requirement: 按日期和数据项目分享 ZIP

App SHALL 允许选择 UTC+8 起止日期以及一个或多个数据项目，包含训练记录、步数、热量消耗及心率；生成 ZIP 后可从 Android 保存或分享。ZIP MUST 仅含所选数据及其范围信息，日期两端均包含；不得包含连接凭据或其他应用设置。既有备份与恢复入口保持独立。

#### Scenario: 导出当天指定项目
- **WHEN** 起止日期都选择当天，同时勾选训练记录、步数、热量和心率
- **THEN** ZIP 包含当天四类资料，保留原值及单位，不包含其他日期或未勾选的项目，且可通过系统分享

#### Scenario: 仅导出离线未同步训练
- **WHEN** 后端不可达，用户只选训练记录，范围内有手机已保存但未上传的组
- **THEN** ZIP 包含这组实际数据，不要求联网或访问健康接口

### Requirement: 健康资料区分完整、缓存和缺失

导出健康资料时 MUST 区分成功读取的在线数据、已保存的本机缓存和未取得数据。未取得值不得记为零或已确认空白；无法取得的日期及项目必须能从导出结果辨认。

#### Scenario: 健康明细未下载且后端不可达
- **WHEN** 所选两天中只有第一天已缓存步数，第二天无法从后端获得
- **THEN** 包内保留第一天已缓存的真实步数，明确标明第二天的步数缺失，训练数据仍可导出

#### Scenario: 在线心率有多页
- **WHEN** 某日有多页心率记录且健康接口可达
- **THEN** ZIP 包含同一读取版本的所有分页记录，不将只取得部分的结果标为完整
