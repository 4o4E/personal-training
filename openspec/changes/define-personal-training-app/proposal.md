# Proposal

## Why

现有训练应用不能同时满足中文使用、按实际器械安排训练、对应拉伸、原生组间休息提醒，以及由助手直接安排计划和读取记录的需要。建立只供本人使用的安卓训练应用，减少训练现场记录和计算休息的操作。

## What Changes

本变更记录用户已经确认的目标与选择，不表示应用已经实现，不启动应用代码编写。

- 原生 Kotlin + Jetpack Compose 安卓应用；原生通知、定时唤醒和锁定屏幕后的休息提醒为最高优先级，不考虑 iOS。
- 以 N 分化和可配置训练部位组织训练，根据所选健身房的实际器械选择、替换动作，预览接下来几天的训练部位。
- 训练前安排计划，训练中按照列表完成各组，点击完成一组后进入组间休息；记录实际重量、次数和组数。
- 保留不同器械各自的 kg、lb 等原始计量单位和重量含义，不以统一换算显示代替器械上的读数。
- 训练动作与拉伸均提供图解、使用方式和多个候选；根据训练动作自动匹配对应拉伸。
- 动作素材采用统一风格插画或动画，优先免费来源，允许 Hevy 素材作为个人使用的临时补充；素材可以替换，不改变动作身份及历史记录。
- 应用连接自有后端同步；提供数据导入、导出和开放接口，另行开发操作 skill，通过与 App 相同的接口安排计划、读取记录供分析。
- 不设账号密码，使用唯一 token 鉴权；未来浏览器仅用于数据浏览，不承担另一套训练流程。
- 使用官方 OpenSpec 管理规范与决定；项目级安装 `4o4E/skills` 的 `feat/openspec-decisions` 工程技能。
- 项目仅供本人使用，不以公开分发、商业化或合规审查作为当前范围。

## Capabilities

### New Capabilities

- `android-training-runtime`：原生安卓训练体验、组完成操作与可靠的组间休息提醒。
- `training-programs`：N 分化、训练部位、提前计划、未来安排预览和动作替换。
- `gym-equipment`：健身房、可用器械、器械原始单位及动作选择条件。
- `exercise-stretch-library`：动作教学、肌肉图解、训练对应拉伸、多个候选与可替换素材。
- `training-data-access`：实际训练记录、自有后端同步、导入导出、唯一 token 与共享开放接口。
- `read-only-web`：未来浏览器的数据浏览边界。
- `project-workflow`：官方 OpenSpec、指定分支的项目级工程技能和单人私用边界。

### Modified Capabilities

无。当前没有已发布的应用规范。

## Impact

- 新增个人训练应用的需求规范和后续实施任务；当前仅调整项目规范与开发工作流程。
- 后续涉及安卓客户端、自有后端、动作及拉伸资料、数据接口和操作 skill；不创建账号密码系统或 iOS 客户端。
- 现有 `record/` 训练记录和 `misports/` 采集能力保持原样，不能把小米云端运动摘要误认为健身房力量训练记录。
- 后续用户确认的 Ktor + SQLite、完整离线训练、轮换规则、拉伸加入方式及独立数据库授权，由 `../implement-personal-training-app/` 记录并跟踪实现。
