# Spec Delta

## Purpose

约束个人训练应用的开发工作方式，使用官方规范流程持续保存用户已经确认的需求与决定，并将工程技能安装在项目内，使后续工作能够继承相同上下文而不影响其他项目。

## ADDED Requirements

### Requirement: 已确认决定通过官方 OpenSpec 维护

项目 MUST 使用官方 OpenSpec 工作流程记录用户已经确认的需求、范围和架构决定，区分确认事项与助手建议，不建立另一套重复的架构决定存储。

#### Scenario: 用户确认新的架构选择
- **WHEN** 用户在讨论中明确确认一个架构选择
- **THEN** 相应决定通过官方 OpenSpec 流程写入本项目的规范或变更材料，未确认的建议不能被标为已接受

### Requirement: 指定分支的工程技能采用项目级安装

项目 MUST 使用 `4o4E/skills` 的 `feat/openspec-decisions` 分支提供的相关工程技能，并将其安装在项目范围内、保存来源分支信息，不以全局 skill 安装替代项目接入。

#### Scenario: 在当前项目使用工程技能
- **WHEN** 助手在本项目进行领域建模、规范记录或代码实施
- **THEN** 可以读取项目内安装的对应技能及其来源分支信息，而不是依赖其他项目或用户级目录中另外安装的技能

### Requirement: 保持单人私用范围

项目 SHALL 面向本人使用，优先支持安卓，不要求 iOS 或公开分发；当前开发不得以分发准备、商业化或合规审查作为前置任务。

#### Scenario: 安排应用开发工作
- **WHEN** 将确认需求转化为后续实施任务
- **THEN** 任务服务于个人安卓训练与自有后端使用，不要求先建设账号密码系统、iOS 客户端或公开分发能力

### Requirement: 现有运动资料保持独立

应用开发 MUST 保留工作区现有训练记录及小米数据采集能力，未经专门迁移不得覆盖原始资料，也不得将缺少健身房力量训练详情的运动摘要当作完整训练历史。

#### Scenario: 应用开始建立自身训练记录
- **WHEN** 后续实现应用的数据存储和导入能力
- **THEN** 当前训练记录与小米采集资料仍保持原样，只有实际存在的力量训练详情才可作为相应训练的记录来源
