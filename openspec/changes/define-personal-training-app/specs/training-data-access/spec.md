# Spec Delta

## Purpose

通过自有后端保存和同步训练资料，并向应用及助手提供同一套可鉴权的业务接口，使训练前安排计划、训练后读取真实记录及数据迁移不依赖手动抄写或自动操作用户界面。

## ADDED Requirements

### Requirement: 应用与自有后端同步训练数据

应用 SHALL 连接用户自己的后端同步训练计划与实际训练记录，后端 SHALL 提供这些数据的业务读取与修改能力。

#### Scenario: 训练后读取实际完成情况
- **WHEN** 用户在应用中完成训练并且该次记录已成功同步至后端
- **THEN** 获得授权的助手可以通过业务接口读取该次真实完成的动作、各组重量、单位和次数，而不是读取计划值作为完成结果

### Requirement: 应用与操作 skill 使用同一套业务接口

系统 SHALL 提供开放的业务接口，并提供调用这些接口的操作 skill；App 与操作 skill MUST 使用同一套业务规则操作计划和记录，助手无需直接修改数据库或自动点击应用界面。

#### Scenario: 助手提前安排训练
- **WHEN** 用户要求助手安排后续训练，助手通过操作 skill 调用业务接口写入计划
- **THEN** 应用同步后可直接展示并执行该计划，接口操作与应用内操作具有相同业务含义

#### Scenario: 助手分析已完成的训练
- **WHEN** 助手通过操作 skill 查询指定时间范围的已同步训练记录
- **THEN** 返回的数据足以区分训练计划与实际完成情况，并保留动作、日期、组数、重量、原始单位和次数供分析

### Requirement: 唯一 token 鉴权且不设置账号密码

系统 MUST 使用唯一 token 对业务接口进行鉴权，不设计账号注册或密码登录流程；未提供有效 token 的请求不得读取或修改个人训练数据。

#### Scenario: 通过 token 连接后端
- **WHEN** 应用或操作 skill 使用有效 token 请求个人训练数据
- **THEN** 可以按照业务接口访问数据，不需要先创建账号或输入账号密码

#### Scenario: 未授权的数据请求
- **WHEN** 请求未提供有效 token
- **THEN** 后端拒绝读取或修改个人训练数据

### Requirement: 训练资料可以导入和导出

系统 SHALL 提供训练资料的导出和导入能力，覆盖计划、实际记录及其关联的动作、健身房和器械资料；迁移 SHALL 保留动作关联、原始重量单位和重量含义，不将计划组误记为已完成组。

#### Scenario: 导出后重新导入训练资料
- **WHEN** 用户导出一份包含混合单位训练记录、计划和相关器械信息的资料，再将其导入一个空的数据环境
- **THEN** 可以恢复对应计划、实际记录及关联资料，kg、lb、单侧与总重量含义保持不变，未完成的计划不变成训练历史
