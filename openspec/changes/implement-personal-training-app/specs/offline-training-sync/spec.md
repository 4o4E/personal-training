# Spec Delta

## Purpose

让用户在健身房网络不可用时仍能按已下载的计划和教学完成训练，把实际完成情况可靠保存在手机，并在恢复网络后同步到自有后端，避免不同入口修改同一计划时丢失数据。

## ADDED Requirements

### Requirement: 已下载资料支持完整离线训练

应用 MUST 在断网时支持读取已下载计划和教学、选择动作、记录实际组及完成训练；计时提醒继续原生执行，未同步数据不得显示为已同步。

#### Scenario: 断网完成训练后同步
- **WHEN** 用户在无网络时完成训练，之后恢复与后端的连接
- **THEN** 本地保留的实际训练可以同步至后端，助手可读取相同记录，重复同步不会增加重复训练或重复组

### Requirement: 同一数据的并发修改显式处理

系统 MUST 使用版本识别同一份数据的并发修改，不得静默覆盖手机或助手的改动；用户可以查看冲突并明确选择保留本地或服务器内容。

#### Scenario: 离线修改的计划与服务器版本冲突
- **WHEN** 手机离线修改一份计划，助手也修改同一份计划，然后手机尝试同步
- **THEN** 显示冲突及两份内容供选择，训练历史不被改写，其他没有冲突的训练记录仍能同步

### Requirement: 训练开始后保留计划内容

实际训练 MUST 保存开始时的计划内容，后续计划或素材变更不得改变已开始训练的目标要求和实际完成组。

#### Scenario: 训练开始后助手调整未来计划
- **WHEN** 用户已经开始训练，助手修改原计划的动作或组要求
- **THEN** 当前训练仍保留开始时内容，修改应用于后续计划而不改变当前实际记录

### Requirement: 独立数据库与可恢复的数据包

系统 SHALL 使用应用自己的独立数据库，提供带格式版本的 JSON 数据及素材 ZIP 包的导入导出；原始单位、动作身份、计划与实际记录关系必须保留，不修改小米数据库和原始训练文档。

#### Scenario: 导出并在空环境恢复
- **WHEN** 导出包含素材、混合单位计划与实际记录的数据包并导入空环境
- **THEN** 数据关系和素材可恢复，未完成计划不变为完成记录，原有运动资料仍保持原样
