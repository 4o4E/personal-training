# Design

## Context

完整功能要求来自 `../define-personal-training-app/specs/`；本变更实现这些要求，新增三份规范记录本次确认的业务规则。用户要求确认结束后直接开始开发。

## Goals / Non-Goals

**Goals:** 安卓原生训练和可靠休息提醒优先；完整离线训练；自有后端与操作 skill 使用同一接口；保持原始训练含义及可恢复数据。

**Non-Goals:** 不开发 iOS 或浏览器客户端，不创建账号密码体系，不改变原始运动资料，不建设多人协作。

## Decisions

### 已确认决定

记录时间：2026-10-21 19:09:40 UTC+8。以下来源均为用户在实施确认表单中的实际选择，状态为已确认。

1. **后端 Ktor + SQLite**：用户选择“Ktor + SQLite”，没有选择 FastAPI。后端与安卓均使用 Kotlin；只部署一个应用后端与持久化目录，不单独维护数据库服务。
2. **完整离线训练并联网同步**：用户选择“完整离线训练，联网后同步”。手机使用 Room；已下载计划、教学和图片可离线访问。计划并发修改显式提示，训练开始后保留当时内容。
3. **完成后轮换，可指定日期**：用户选择“按完成顺序轮换，可指定日期”。休息和取消不推进；未指定日期的计划仅展示后续顺序。
4. **拉伸自动推荐，手动加入**：用户选择“自动推荐，手动选择加入位置”。不自动插入末尾拉伸段，用户或助手决定候选和列表位置。
5. **独立数据库授权**：用户选择“同意该结构，允许创建独立数据库”。授权范围为部位、动作与拉伸对应、独立素材、健身房及器械、N 分化顺序、日期计划与计划组、实际训练与实际组及计划快照；另存同步版本和计时状态。导入导出采用带版本 JSON 与素材 ZIP，不修改原始资料或 misports.db。
6. **定时唤醒与普通通知**：2026-10-22 用户追加确认“不需要处理极端场景”“不要用系统的闹钟响铃”“只要唤醒自己然后发通知提示”。到时唤醒应用并发送普通通知，提示音与振动遵循通知设置，不使用闹钟铃声或全屏提醒；验证日常训练、切换应用和息屏场景。
7. **CI 发布镜像，用户手动部署**：2026-10-22 用户确认“配置ci构建镜像发到ghcr，项目中预置compose文件，我手动部署”。GitHub Actions 构建并验证后端镜像后发布至 GHCR，部署使用 `latest` 和持久数据卷，不在当前电脑或服务器上自动部署。
8. **私有源码与公开镜像分别配置**：2026-10-22 用户确认“github项目private，但是ghcr公开”。源码仓库保持 Private，GHCR 容器包设为 Public，部署端匿名拉取；首次创建包后按 GitHub 官方页面设置公开可见性，CI 对发布的镜像执行未登录拉取检查。
9. **首次发布目标**：2026-10-22 用户选择新建 `4o4E/personal-training` 私有仓库。只上传应用工程、OpenSpec、项目技能及 CI 必要文件，不上传个人训练记录、小米数据、凭据或临时资料；在该仓库首次执行发布工作流并验证公开镜像，不部署服务器。

### 实施方式

- 独立 Gradle 工程位于 `training-app/`；`shared` 保存可序列化的业务定义及部位/器械匹配规则，`server` 为 Ktor 应用，`android` 为原生客户端。按同一业务定义处理离线与联网数据，避免两套业务含义。
- 服务端 SQLite 以有类型的业务文档保存上述实体，计划组与训练开始时内容作为所属计划/实际训练的聚合数据，保证单份记录原子更新；业务入口按类型解析和校验，不能通过任意 JSON 绕过约束。数据库只包含本应用数据。
- 通信使用带版本的 JSON 业务接口与 Bearer token。变更包含实体种类、稳定标识、基准修订和内容；服务器按实体原子接受或返回冲突。重复提交已接受的相同内容不产生重复记录，删除用同步标记传播。
- 手机本地保存业务文档、已知服务器版本、待同步标记、冲突内容和计时状态。后台同步只负责数据，不负责休息计时；用户可主动同步，界面区分待同步、冲突和已同步。
- 实际训练包含开始时计划快照，各组计划要求与实际完成字段分开。完成或取消状态明确区分；分化下一项从最近完成训练及当前顺序计算，不因日期经过而推进。
- 本地和服务器对同一份未开始计划的不同修改显示两份可理解内容，明确选择保留哪份。其他无冲突的实际记录不被该冲突阻止。
- 休息与拉伸计时先持久化结束时间，再使用 `AlarmManager.setExactAndAllowWhileIdle(RTC_WAKEUP, …)` 唤醒接收器并发送普通通知。不注册用户可见的系统闹钟，不使用闹钟音频类别或全屏界面。后台同步与计时分别调度。
- 器械关联动作所需的器械类别；默认值可以来自器械，实际组仍保存自己的数值、单位和读数含义，禁止统一换算替代原始显示。自重动作无需虚构重量。
- 动作资料采用人工核验的中文说明、部位和器械关系，提供统一风格实际插画；肌肉图使用可核验的已有图形。素材与动作分开，图片更新不改变动作标识。素材选择与内容核验属于实施，不再次要求用户选择底层库。
- App 为普通中文表单和动作列表，不要求用户编辑 JSON。操作 skill 使用同一业务接口管理资料、计划和查询历史；其接口说明与 CLI 一起交付。
- 导出包含格式版本、业务数据及实际素材文件；导入校验格式和关联，同一标识存在不同内容时要求显式处理，不能静默覆盖。token 不进入导出包。
- GitHub Actions 在实际仓库默认分支的后端变更或手动触发时发布 Linux amd64 镜像，地址从仓库上下文生成并规范为小写。构建中执行已有服务端行为回归，容器通过启动与鉴权检查后才推送；依赖、素材和业务代码保持独立层，并使用 Actions 构建缓存。
- 部署 Compose 只拉取 GHCR 镜像，不要求服务器复制源码或本地构建。仓库名由部署目录 `.env` 提供，CI 摘要给出实际值；保留独立数据卷和本机反向代理端口，业务 token 不写入发布工作流。

## Risks / Trade-offs

- [系统提醒授权与运行限制] → 在已连接的安卓真机上验证日常后台、息屏及连续提醒，明确通知与定时唤醒授权状态；不扩展强制省电、终止进程等极端场景。
- [离线修改产生冲突] → 保留两份并明确选择，不采用最后一次写入静默胜出的方式。
- [通用存储失去业务约束] → 共享类型定义和业务入口进行必要校验，真实接口验证关系与错误路径。
- [素材实际姿势与说明不符] → 收录前检查真实图示，保留可替换的素材关联，不将未核验内容称为已核验教学。
- [测试记录污染个人历史] → 验证使用独立数据目录，完成后不把验证数据留作个人训练记录。

## Migration Plan

新建应用自己的数据库和持久化目录，既有运动资料不迁移、不修改。提供 Docker 部署和直接运行方式；验证使用独立目录与随机 token。数据库后续增加新业务含义时按用户规则先确认。发布前交付真实可安装 APK、后端运行方式、数据导入导出及操作 skill 文档。
