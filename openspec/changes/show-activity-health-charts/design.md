# Design

## Context

动机参见proposal.md。DayHistoryDialog使用单一LazyColumn，先展示运动再调用healthDateDetails；健康概览目前主要展示样本数量。HealthUiState已有按日期的汇总、实际采样及分页缓存状态，HealthRecord.measuredAt为毫秒。运动摘要和用户修改的ActivityRecord起止独立保存。HealthSyncCard是日历常驻内容，同时承担采集轮询、重试和冲突入口；MainActivity的TopAppBar可提供actions。TrainingRepository.retryAll依次同步训练、素材和健康，并可能发起采集请求，不能仅凭训练syncStatus提前宣布整个操作完成。

## Goals / Non-Goals

**Goals:** 复用既有数据与持久化规则，明确区分全天概览、运动时段采样和设备摘要；将同步交互从长期显示变为一次操作的提示和按需问题处理。

**Non-Goals:** 不新增健康API或数据库结构，不自动创建、改写活动记录或用户保存的运动起止，不合成运动样本、插值或将日常稀疏采样用作运动曲线，不更改训练计时、分化、同步冲突策略与原始健康量值，不自动发布或更新正式手机应用。

## Decisions

### 已确认决定

用户要求“当天一天的数据给一个概览”及“运动时的数据给一个图标并标记开始和结束时间”，随后选择“按时间变化的图表”。运动图表的输入确定为小米运动真实心率明细，不是全天日常心率采样；运动采样由采集器复用现有健康心率 API 上传，并按稳定来源标识关联已有活动。范围同时覆盖力量训练与自定义运动，并保留统一草稿编辑。

### 实施选择：全天概览与详情分离

HealthHistoryScreen提供全天概览与可展开明细的列表内容，DayHistoryEditor将概览放在运动之前；主睡眠选择已有规则的最长段，身体概览使用当天最新真实测量并保留完整明细。原始样本计数保留在按需详情而非主要概览，不更改后端汇总模型。读取中和缺失只影响对应指标，已有缓存继续显示。

### 实施选择：运动真实样本与原生绘图

新增ActivityHeartRateChart.kt承载小型数据整理函数与Compose绘图入口，DayHistoryEditor的力量训练、自定义运动、设备运动及HealthHistoryScreen运动明细共用它。输入为用户保存的活动起止、HealthUiState中已缓存的真实心率记录和可用状态。图表只选择闭区间内 `source=xiaomi_workout`、`sampleType=active` 且BPM大于零的真实记录，不把稀疏日常采样当成运动数据。相同毫秒有多个运动来源时按sourceId排序并保留最前一条。以2.5秒为相邻样本最大连线间隔：例如17:52:00至17:52:01可连线，17:52:01至17:52:04的3秒缺口断开；不插值、不补造，也不为逐秒采样逐点绘制圆点或生成冗长无障碍文本。绘图保留真实时间轴、采样点、起止时间标签、心率单位与可读语义。没有运动样本时明确显示无匹配运动心率，不退回日常点；单点只显示该真实点。跨日范围提示缓存覆盖可能不完整，缓存未完整读取时标明限制；已读完时不额外显示状态提示。时段范围始终由用户保存的活动起止决定，不改写记录；设备摘要不替代采样。

### 实施选择：同步入口与一次性结果

新建HistorySyncControls.kt放置右上角图标、Snackbar和按需同步详情；MainActivity仅在运动记录路由展示图标与对应提示，HistoryScreens移除旧卡片。图标正常点击执行同步，存在问题时提供重试和详情选择，详情保留冲突处理与请求小米采集。进行状态必须覆盖整次手动retryAll，结果在实际操作结束后产生一次；新同步事件与持久状态分离，避免重新进入页面重复提示。后台自动同步继续使用既有WorkManager，自动完成事件只在运动记录可见时反馈，不把历史成功状态作为新事件。详情保留最近同步时间和各阶段失败原因，不长期显示。采集轮询从旧卡迁移至新交互宿主，保持仅页面可见时轮询。

### 实施与验收分工

实施包含运动图表的三个入口、真实样本接入、离线缓存适配及对应使用/API文档。图表共用现有HealthUiState和健康记录模型；采集器通过已有心率导入API写入运动明细，不修改健康表结构。主代理负责集成及真实后端、手机验收；未执行的构建、测试或生产/真机验收不记作已完成。

## Risks / Trade-offs

- 训练同步已结束但健康尚在读取 → 操作完成事件等待整次手动重试；自动阶段提示不声称所有健康采集已完成。
- 设备摘要时间与用户时间不同 → 图表使用用户保存的起止，摘要明确保持设备统计，互不改写。
- 运动采样缺失、重复时间、跨日范围或缓存未完整读取 → 仅显示命中的实际运动记录，同毫秒重复值确定性去重，显式提示无数据或覆盖不完整，跨日不暗示完整；不使用日常稀疏点，不跨明显缺口连线。
- 删除常驻同步卡同时丢失轮询或冲突操作 → 在新的同步宿主和详情中完整迁移，实机验证失败、恢复、冲突入口和返回无重复提示。
- 验收污染正式资料 → 使用隔离调试环境与备份恢复；正式应用和生产数据不得修改。

## Migration Plan

采集器通过既有心率API上传小米运动逐秒明细，以稳定来源ID和真实毫秒时间写入已有心率记录。无需新增API、数据库表或字段；现有分日分页、Room离线缓存与v6备份继续承载样本。已有运动记录用设备运动样本及用户保存的活动范围展示，活动记录本身不改写。
