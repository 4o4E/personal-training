# Proposal

## Why

日期弹窗需要区分全天健康概览与具体运动期间的数据，现有样本计数和逐条文本无法直观看到运动心率变化。常驻同步状态卡占据日历空间，用户已确认改为右上角图标和一次性结果提示。

## What Changes

- 日期弹窗顶部展示全天步数、活动消耗、主睡眠、静息心率与身体指标，原始明细按需展开。
- 力量训练、自定义运动及设备运动的三个图表路径均按已保存的活动时间范围展示真实小米运动明细心率，标记开始和结束；设备摘要独立展示，不混算。
- 图表仅读取 `source=xiaomi_workout` 的运动样本，日常稀疏采样绝不伪装成运动曲线；明显采样缺口断开、不插值补造，无匹配运动样本时明确提示。
- 采集器使用现有心率导入 API 上传真实运动样本，`sampleType=active`、`source=xiaomi_workout`，以稳定的 `workout:<activity.source_id>:<offset_s>` 来源标识幂等关联已有活动；使用既有离线缓存，不改数据库结构。
- 保留紧凑训练组记录、单一修改入口、整窗草稿与离线保存。
- 移除常驻同步状态卡，在运动记录右上角提供同步图标；一次同步结束短暂提示一次，失败可重试，原因和冲突按需打开。
- 自动同步及既有服务器采集能力保持，生产数据和正式应用不变。

## Capabilities

### New Capabilities

无新增独立能力。

### Modified Capabilities

既有能力位于已完成未归档的变更中，继续沿用相同路径。

- `health-data`：全天概览与运动时段心率图表。
- `cloud-training-state`：低干扰同步入口、结果提示与按需问题处理。

影响Android日期弹窗、健康展示、运动记录顶栏及同步提示协调；健康运动明细通过既有心率API和离线缓存读取，不新增API或数据库结构，不改写设备活动时间或用户保存的活动范围、个人原始训练记录或小米源库。
