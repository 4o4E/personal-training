# Spec Delta

## MODIFIED Requirements

### Requirement: 查看已接入的日常健康数据

系统 SHALL 在日期弹窗顶部集中展示全天概览，包括实际取得的步数、步行距离、活动消耗、静息心率、主睡眠时长和身体指标，不以样本条数替代健康量值。睡眠、身体测量及其他原始明细可在同一弹窗按需展开；小米原始指标保持只读。来源单位、测量时间与缺失状态 MUST 保留，不把其他日期测量冒充当天，也不将不同热量口径相加。

#### Scenario: 查看全天健康与当天运动
- **WHEN** 当天有睡眠、步数、身体测量及羽毛球
- **THEN** 弹窗先展示全天概览，再展示羽毛球及运动时段数据；全天活动消耗与该场运动消耗各自标明含义

#### Scenario: 查看同日多次测量
- **WHEN** 同一天存在多次身体测量
- **THEN** 概览展示当天最近一次实际测量并保留时间，所有测量仍可展开查看，不按日期或同一体重合并删除

#### Scenario: 某日没有身体测量
- **WHEN** 当天没有实际身体测量
- **THEN** 不用其他日期数据填充当天身体指标；步数、睡眠等已有内容仍能查看

## ADDED Requirements

### Requirement: 按真实运动样本查看心率图表

力量训练、自定义运动及设备运动的图表 SHALL 仅使用已保存运动时间范围内真实的小米运动心率样本；图表 SHALL 保留该范围的开始、结束及时间显示，不得以日常 `passive` 稀疏采样、设备摘要均值或合成值充当运动采样。图表 SHALL 只接受 `payload.source=xiaomi_workout`、`sampleType=active` 且BPM大于零的记录。同一毫秒存在多条匹配来源时 SHALL 按 `sourceId` 排序并仅保留最前记录。相邻样本间隔超过2.5秒时 MUST 断开折线，不插值、不补造；逐秒采样不得逐点绘制圆点或生成冗长无障碍文本。没有匹配运动样本时 MUST 明确提示无运动心率，不得回退到日常采样。设备摘要的统计值独立展示，不取代实际运动采样。

#### Scenario: 力量、自定义与设备运动使用同一运动样本
- **WHEN** 力量训练、自定义运动或设备运动有完整起止，并且已有对应的小米运动心率明细
- **THEN** 三个图表路径均只按用户保存的起止范围筛选真实运动样本，保留开始、结束、时间刻度和心率单位，不改写活动记录

#### Scenario: 日常稀疏点不冒充运动曲线
- **WHEN** 活动范围内只有 `sampleType=passive` 日常心率点，或只有其他来源的心率点
- **THEN** 图表明确显示没有匹配运动心率采样，不绘制日常采样折线

#### Scenario: 运动采样明显缺口
- **WHEN** 相邻运动样本时间为17:52:01和17:52:04，相差3秒
- **THEN** 图表在该间隔断线，不插值、不生成缺失样本

#### Scenario: 重复时间来源
- **WHEN** 多条匹配的运动来源时间戳相同
- **THEN** 图表只保留按 `sourceId` 排序最前的一条，避免同一时刻重复绘制

### Requirement: 通过既有心率API保存真实运动样本

采集器 SHALL 通过现有心率导入API上传小米运动真实心率明细，并以稳定的 `sourceId=workout:<activity.source_id>:<offset_s>` 关联已有设备活动。每个样本的 `payload.sampleType` MUST 为 `active`，`payload.source` MUST 为 `xiaomi_workout`，`measuredAt` MUST 使用真实样本时间戳（毫秒），BPM MUST 是实际大于零的读数，不得合成；相同样本重复导入 MUST 幂等。系统 MUST 复用现有健康记录表、分页及离线缓存，不新增数据库表或字段。

#### Scenario: 导入已有活动的运动明细
- **WHEN** 采集器取得已有设备活动的真实心率样本
- **THEN** 通过既有API按稳定活动来源和样本偏移上传真实读数，保存后可按实际时间与已有活动范围匹配显示，不创建或改写用户活动记录

#### Scenario: 重复导入相同运动样本
- **WHEN** 采集器因重试再次提交相同来源ID及相同运动心率内容
- **THEN** API按现有幂等规则确认不变，不创建重复样本

### Requirement: 图表保持缓存覆盖范围的真实含义

系统 MUST 区分没有起止、没有运动样本、采样尚未取得、部分缓存及已读完但范围内没有匹配运动样本。未知时间不猜测；单个样本展示真实点而非虚构整条曲线；未测量部分不补零。既有Room离线缓存 MUST 可继续显示运动样本。跨日活动范围或缓存未完整读取时 MUST 明确提示覆盖可能不完整，不能把当前日期的有限缓存描述成完整运动曲线。

#### Scenario: 只有日期的历史力量记录
- **WHEN** 历史记录缺少开始或结束时刻
- **THEN** 保留训练详情和全天概览，不虚构运动时段图表

#### Scenario: 离线单点缓存
- **WHEN** 手机离线且缓存的活动范围内只有一个真实运动样本
- **THEN** 展示该样本真实时刻的单点，保留缓存内容，不补造起止心率、零值或连续曲线

#### Scenario: 跨日或部分缓存
- **WHEN** 活动范围跨越UTC+8日期边界，或该范围的数据尚未完整缓存
- **THEN** 只展示已缓存并落在活动范围内的真实运动样本，同时说明缓存范围可能不完整
