# Design

## Context

动机与范围见 `proposal.md`。已核对的实现基础：

- `MainActivity` 通过tab字符串和多个布尔值控制页面，设置使用弹窗；`StartOverview`包含方案选择和整轮预览，`HistoryScreen`是列表及弹窗详情。
- Room保存完整JSON文档及dirty/conflict信息，`TrainingRepository.sync`已经按修订号合并并保护网络等待期间的新改动。启动恢复本地数据，`onResume`只安排WorkManager同步。无需重新实现同步协议。
- `AppPreferences.DeviceChoices`目前把当前方案和各项所选计划放在本机偏好中，后端没有对应业务资料。`nextSlot`按已完成训练推导下一项。
- `WorkoutScreen`已有实际组输入和完成操作，也包含动作编排。`completeSet`本地保存结果与TimerState，`TimerEngine`使用精确定时唤醒和带Chronometer的普通通知；尚未请求实时活动提升展示。
- 当前实际测试设备为一加9R LE2101，Android13/API33，LE2101_11_F.16。官方Fluid Cloud手册要求OxygenOS14及以上且部分机型不支持；Android原生Live Updates接口面向较新系统。9R不能承担原生灵动岛验收。
- 历史导入变更尚未实施，定义仅日期训练、原计划缺失、组内降重与备份版本2。日历必须复用其日期语义，不创建另一种历史格式。

## Goals / Non-Goals

**Goals:** 训练、配置和历史职责分离；云端业务安排可被手机及skill一致操作；离线保存及计时不受网络影响；原生实时活动具有独立真实验收。

**Non-Goals:** 不改手机系统、不引入悬浮窗模拟灵动岛、不使用系统闹钟响铃、不改变既有token认证、不增加账号或浏览器客户端、不改写record与misports、不以本变更代替八次历史记录导入。

## Decisions

### 已确认决定与来源

- 用户明确列出设置独立路由、云端与本地缓存区分、逐组执行与自动计时、全部计划集中调整、日历与云端记录五项要求。
- 用户选择“接着练推”：手动把下次拉日改为腿日，完成后继续推→拉→腿，不补回拉日。
- 用户指定“氧os”，随后指定新无线ADB的一加9R用于验收。
- 在说明9R系统限制后，用户选择“保留原生灵动岛要求”：9R验证训练、同步、普通通知，原生能力仍须支持该能力的氧系统设备实测。
- 用户要求“后续开发工作在你设计好之后由luna完成，你来验收”。采用Luna（GPT-6-Luna）开发；主助手负责设计、接口审查、集成验收与最终证据，所有子代理由主助手管理且不得再派生子代理。
- 用户明确要求灵动岛收起时显示倒计时；到时弹出普通通知并改为正数“额外休息X秒”，不显示负数，不自动完成下一组。
- 用户选择“接受，按这个方案实施”：仅在计时期间运行前台服务，倒计时期间保持CPU运行但不点亮屏幕；额外休息释放CPU唤醒锁，结束休息或训练时停止服务。用户同时允许通知验收期间临时关闭勿扰并在结束后恢复。
- 用户要求“先用没有灵动岛的手机完成开发，adb连上了”；无灵动岛设备的普通通知和后台计时验收不替代支持设备的收起状态展示验收。
- 用户要求“给应用画一个svg哑铃作为图标，另外release设置应用名字”。

### 技术实施决策：独立路由，不用弹窗模拟页面

使用官方Navigation Compose管理三项主页面、Settings及DayHistory(date)等实际目的地，保持单Activity和现有Compose。设置与日期详情隐藏主导航，显示返回按钮；三个主页面保存各自状态。教学与单组编辑仍可使用适合的对话框。

会话与计时继续属于Repository而非导航页面；未提交读数用session/item/set标识保存，切换设置及外观不重置。通知进入固定训练路由，优先显示既有active会话，不重复创建训练。旧布尔设置入口和重复计划选择界面在切换完成后删除，不保留两套导航。

### 技术实施决策：云端安排作为单份业务文档

在现有文档机制增加 `Kind.arrangement`，使用单人固定标识 `current`：

- `programId`：当前方案，可为空表示尚未配置。
- `selectedPlans`：按programId及slotId保存所选planId，保留多个方案的选择，避免不同方案复用slotId时互相覆盖。
- `nextOverrides`：按programId保存下次手动选择，每项包含独立选择标识及slotId。

继续用已有revision、Document、sync及import，不新增独立认证或助手接口。同步支持此kind、备份包含此文档，项目级CLI种类与文档说明同时更新。SQLite和Room仍保存JSON，不更改表、列或Room版本。

手动选择在开始会话时复制选择标识到Session的可选 `arrangementOverrideId`。已有completed会话消费相同标识后，该选择不再生效，下一项按真实完成项推导；cancelled不消费。这样无需在完成训练时额外写另一份状态，也不会把训练过程中刚设置的新选择错误清除。未来计划调整不能改写开始时内容；新选择仅供之后新开训练使用。

删除或修改被当前安排引用的方案、slot与plan，必须同步更新安排中的引用；无效引用在业务写入处拒绝，不能偷偷选择另一份计划。真正没有配置时由调整计划引导，不在训练页自行选择候选。

### 技术实施决策：启动同步与明确的本机持久化状态

初始化先恢复本地资料并呈现可操作界面，然后直接调用已有受互斥保护的同步流程，不依赖WorkManager首次调度时间。前台恢复与网络恢复触发同一流程，WorkManager继续承担离开界面后的同步，不建立第二条上传路径。

沿用本机clean/dirty/conflict划分，补充可持久化的最近成功业务同步时间和明确的连接状态；素材下载状态与业务资料同步状态分别展示。界面只在必要处显示离线、待上传及冲突，不每次操作弹出网络失败提示。资料写入失败仍由真实错误暴露，不以成功提示掩盖。

这里的本地副本不是随时可丢弃的缓存：dirty、进行中训练及计时必须持久保存。只有已同步素材等可重建内容属于缓存。本次不新增缓存清理功能；未来若清理，不得删除未上传记录。

本机旧选择只在迁移中使用：先成功读取云端安排，已存在则使用云端；不存在才用有效旧选择以baseRevision=0创建。断网保留原选择和迁移状态，服务端确认后移除旧业务偏好字段，只留下外观、教程等设备偏好。并发创建冲突沿现有规则处理，不自动覆盖。

### 技术实施决策：逐组训练界面复用真实写入能力

无active会话时只显示已确定的下一次动作清单及开始按钮；有active会话时显示各动作进度与当前待完成组的输入，已完成组收起但可展开修正。保留原始kg/lb及负重含义，拉伸按次数或时长呈现。

提交时锁定明确的session/item/set目标，完成持久化后推进输入焦点并显示休息，不将重复点击解析成下一组。修改已完成结果不重启休息。进度按实际结果与当前有效目标计算，被替换且未执行的目标不计入有效目标数。

训练页仅保留执行、教学、实际结果修正、反馈、结束训练和转往调整入口。动作添加、替换、拉伸加入位置和目标设置移到调整计划；有active会话时提供“本次剩余内容”与“未来计划”的明确区域，复用既有保护已完成组的业务方法。普通结束仍需用户明确操作，不能因计划最后一组被点击就悄悄推进轮换。

### 技术实施决策：日历由实际记录派生

用现有Compose和java.time实现月历，不另存运动打卡表。按UTC+8训练日期将results非空的Session分组，历史日期复用历史导入变更的规则；同一会话跨午夜仍归属其训练开始日，与历史查询一致。推、拉、腿标签来自会话保存的名称或开始时内容，不从当前可变计划反查。

同日多次可显示多个简短标签或数量并在DayHistory(date)完整展示；无记录日期仍可进入空详情。记录增量同步、删除和本机完成组使日历响应更新。详情复用实际结果展示，支持历史日期缺失时间和一组多段重量，不复制另外一套统计规则。

### 技术实施决策：系统原生实时活动与普通通知共享计时

TimerState继续使用已持久化的单一截止时间；剩余秒数向上取整并限制为非负，到时后的额外休息按超过截止时间的整秒数正向累计。仅rest类型进入额外休息，拉伸动作计时结束仍显示结束状态。本机计时增加已提醒标记，复用现有JSON存储，不修改Room或后端表结构。

使用仅在计时期间运行的前台服务，每秒更新普通通知标题与受版本保护的shortCriticalText。通知不使用会越过零点成为负数的系统倒计时。支持API36的设备继续请求原生提升展示，不使用悬浮窗或厂商私有字段。倒计时期间持有带超时的PARTIAL_WAKE_LOCK，到时、取消或训练结束时释放；不点亮屏幕。额外休息不持有CPU唤醒锁，屏幕关闭时停止逐秒文字更新，唤醒后依据原截止时间刷新。

前台服务负责准时到达截止时间，AlarmManager保留同一截止时间的系统唤醒作为补充，两者经过同一本地互斥与持久化已提醒标记，只发一次普通高重要性通知。提醒不依赖网络初始化。到时提醒遵循系统勿扰及渠道设置，不使用闹钟铃声或全屏界面。进入额外休息时保留当前计时通知，点击结束休息、完成下一组、取消或完成训练时清除或替换；过期的旧回调不得影响新计时。

界面和通知复用共享的TimerState.displayText(now)计算：休息倒计时、额外休息秒数、拉伸倒计时或结束文案。导航、读数修正和同步均不改变计时基准。提醒标记只记录本机通知状态，不增加训练组或业务历史。

原生提升展示检查权限和实际promoted结果；支持设备必须验证收起状态持续显示时间、到时提醒和额外休息切换。先完成一加9R的实际功能验收，支持设备不可用时只阻塞原生展示验收，不将普通通知结果当作通过证据。

### 技术实施决策：哑铃启动图标与构建名称

保留SVG原图，并使用相同几何及配色的Android矢量前景和纯色背景组成自适应图标；应用的普通与圆形图标入口引用同一资源。图形采用深绿色背景、浅绿色双层配重片和细握柄，居中斜向排列，完整轮廓位于裁剪安全区。沿用现有构建配置：release名称为“个人训练”，debug名称为“个人训练·验证”，不改包名、签名或版本号。

### 开发分工与共享接口

实施先由一位Luna数据负责人完成共享领域接口、云端arrangement、历史日期配合、备份与仓库同步。历史导入与本变更的Domain修改归同一负责人；主助手审核接口后再分配依赖这些接口的界面工作，避免各自发明状态模型。

接口稳定后可并行给两位Luna：

1. 页面负责人：导航、设置、训练执行、调整计划、日历和每日详情；持有MainActivity及相关Screen文件。
2. 通知负责人：Timers、Manifest及必要通知入口适配；通知目标统一为打开训练，不直接修改导航文件。

数据负责人持有Domain、Repository、AppPreferences迁移、后端、skill及数据文档；页面负责人不得直接更改其接口，通知负责人不得修改训练完成事务。主助手提供完整任务契约，所有子代理跳过中途构建、格式化及测试，完成一批后由主助手集中运行受影响检查与真实使用场景；缺陷交回Luna修复，主助手复验。真实设备操作、生产凭据和导入由主助手掌握，不下发到子代理材料。

## Risks / Trade-offs

- [旧客户端严格解码未知文档类型] → 新客户端与后端作为配套更新，先导出旧版备份，不对旧客户端承诺新arrangement兼容；与历史变更共享版本2备份并继续读取版本1。
- [业务选择从本机迁移导致默认安排覆盖云端] → 仅成功读取确认不存在才创建，保留未迁移偏好直到服务端确认；网络失败不是空数据。
- [完成旧会话清除刚选择的新下次部位] → 以不可变选择标识关联会话，消费仅作用于该标识，不全局清空下次安排。
- [云端计划更新改变当前训练] → 继续使用开始时内容与实际执行条目，未来计划修改不触及active会话。
- [9R不支持原生灵动岛] → 9R完成可运行部分验收，支持OxygenOS设备完成独立原生验收；不声称全部完成，也不擅自升级系统。
- [已有历史日期格式尚未实施] → 共享数据负责人先完成两项变更的共同字段，日历依赖该实际接口；历史导入仍按自己的15项清单执行，不在本变更重复写入生产。

## Migration Plan

1. 主助手确认本设计及共享接口，按用户要求由Luna开发；本次规划不自动执行代码修改。
2. 完成共享领域与云端安排后，再分配页面和通知独立工作；删除本次被替代的页面入口与旧本机业务字段，保留必要的一次性读取迁移。
3. 主助手运行受影响行为检查，在独立真实后端和一加9R验证启动拉取、断网完成组、恢复同步、设置返回、计划轮换、日历、倒计时及后台提醒。
4. 在支持该能力的OxygenOS设备实际验收原生实时活动。未取得设备不阻止其他实现，但阻止该验收项和整个变更宣称完成。
5. 通过既有发布流程准备配套更新，生产部署沿用户现有授权路径进行；不自动升级手机系统、不绕过auditro只读权限。更新前备份，新增格式写入后不能直接回退旧程序并继续使用同一数据。
