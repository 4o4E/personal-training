# Spec Delta

## MODIFIED Requirements

### Requirement: 查看已接入的日常健康数据

系统 SHALL 在运动日历的日期弹窗中查看当天步数、距离、热量、心率、静息心率、睡眠、体重和已有体成分指标，健康明细在同一弹窗内展开，不再切换到独立健康浏览页面。量值 MUST 保留来源单位、测量时间与缺失状态，不将无数据视为零，不相加不同热量口径。健康读取沿用训练鉴权，进入弹窗编辑时原始健康指标仍只读。

#### Scenario: 某日没有体成分测量
- **WHEN** 用户打开有步数和心率但无体成分测量的日期
- **THEN** 同一弹窗显示已有指标，体成分未记录，不用其他日期测量冒充当天数据

#### Scenario: 查看同日多次测量
- **WHEN** 同日有两个不同来源标识的体成分测量
- **THEN** 两次测量均可展开查看，时间与缺失字段保持，不按日期或相同体重合并删除

### Requirement: 健康数据不参与力量轮换

日常指标和独立小米运动 MUST 不创建力量组、不消费分化安排。健康与运动在同一日历日期弹窗展示，只有步数或睡眠的日期也可打开，但不产生运动训练标记。

#### Scenario: 只有步数的一天
- **WHEN** 某天有8000步但没有实际训练或运动摘要
- **THEN** 点击日期可在弹窗查看8000步，日历不虚构训练名称或完成组数，下次训练部位不变

## ADDED Requirements

### Requirement: 来源运动在日期弹窗关联展示

日期弹窗 SHALL 通过稳定来源标识将小米运动摘要附在对应运动记录中，展示已有平均心率、最高心率和消耗等信息，不按名称或时间猜测匹配，不将同一场运动再显示为第二条运动。用户填写的起止、名称和备注与设备原始统计保持独立；未关联来源或未下载的明细不得冒充无数据，设备记录时长不改为起止差。

#### Scenario: 用户时间与设备时间不同
- **WHEN** 羽毛球用户记录19:00至22:00，关联设备摘要记录19:42至22:14和9078秒运动时长
- **THEN** 用户起止与独立记录时长分别保持，已有设备心率和消耗在同一运动块内显示，原始时间可在只读来源信息中查看，不重复一条羽毛球

#### Scenario: 日期弹窗离线查看
- **WHEN** 用户离线打开已下载健康数据的日期
- **THEN** 保留已有汇总与详情并可展开，未下载数据明确尚未下载；仍可编辑和保存用户运动记录，不在弹窗重复全局同步状态
