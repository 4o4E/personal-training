# Proposal

## Why

同一天的健康数据与运动记录分属两个查看入口，日期弹窗的逐组按钮和留白占用过多空间，训练反馈缺少编辑入口。用户已确认将同日内容合并，并用一次修改、取消或保存操作处理整个弹窗内的可编辑内容。

## What Changes

- 日历日期弹窗统一展示训练、其他运动及当天健康数据；移除独立健康浏览页面的切换入口，保留健康明细展开能力。
- 小米来源运动通过既有来源标识关联心率、消耗等统计，不重复显示同一场运动；只有健康数据的日期也可查看，但不标记完成训练。
- 阅读状态采用紧凑动作和组记录布局，取消逐组修改按钮。
- 单一修改入口开启整窗草稿：编辑实际重量和单位、次数或时长、分段读数、训练反馈，以及其他运动的名称、日期、时间、时长、距离和备注。
- 小米原始健康指标只读。删除进入草稿，统一保存才执行；取消放弃全部修改；未保存修改在外侧点击或返回关闭时需要确认放弃。
- 一次本地事务保存整窗修改，继续使用现有离线队列和同步冲突处理。

## Capabilities

### New Capabilities

无新增独立能力。

### Modified Capabilities

既有能力目前保存在已完成但未归档的变更中，本次沿用原能力路径。

- `training-calendar`：同日紧凑阅读、单一编辑入口、可编辑反馈和整窗草稿提交。
- `health-data`：健康浏览整合到日期弹窗，原始健康信息只读并关联来源运动。

## Impact

影响 Android 日期弹窗、健康展示组件、训练记录编辑及本地事务保存入口；沿用现有数据模型、Room 表和后端同步接口。不会修改个人原始训练记录、小米采集脚本、生产数据或正式手机数据。
