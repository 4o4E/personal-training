# Design

## Context

参见 proposal.md。现有安卓入口固定使用浅色主题和五个底部页面；分化编辑器从空名称、空部位开始，计划与每组要求需要分别填写。动作选择、计划预览和 WorkoutScreen 已有教学能力。首页当前将已完成训练引用的所有计划标识纳入排除条件；由该逻辑可推断，重复使用同一批无日期计划时，完成一轮后待执行列表会为空。本次尚未在生产环境复现该情况。

现有 Program、SplitSlot、Plan、PlanItem 和 SetTarget 已能承载有序部位、可选健身房、动作与组数。已有 Session 具有独立标识和开始时内容，可以多次引用同一计划并保持各次实际记录独立。当前静态目录有实际肌肉、动作、器械及教学素材，不需要引入在线生成服务。

用户已经在生产和手机配置真实使用环境。本次规划和后续验证不能通过清除该应用数据取得干净环境。

## Goals / Non-Goals

**Goals:** 默认路径从选择少量候选到预览确认，再直接训练；整轮选定、按日微调；训练主导航简化；教程和完整深色外观；保护已有连接、计划、原始读数与历史。

**Non-Goals:** 不改变唯一 token、离线同步、训练数据格式、拉伸手动插入或原生普通通知；不新增账号、在线模型、自动进阶或固定每周升级规则；不改生产部署，不自动重置数据。

## Decisions

### 已确认需求与决定

记录时间：2026-10-22 UTC+8。

1. 用户要求默认提供三、四、五分化，选择分化后按相应部位提供多套计划，动作数量与组数也通过选择配置，并客观说明区别。
2. 用户在计划范围选择中明确选择“整轮先选一套，再按日调整”。首次选择覆盖全部分化项的一套计划，不强迫分别完成三至五次候选选择；之后保留某天及某动作的调整。
3. 用户要求底部仅为“开始训练”“调整计划”“运动记录”，左上角菜单收纳设置及可选健身房；动作教学进入具体选择和训练场景，不再独立设主入口。
4. 用户要求首次进入有功能及自有后端配置教程，并支持深色模式。
5. 用户选择“创建改版方案”，授权本变更的提案、规范、设计和任务材料；当前仅记录，不实施应用或生产改动。

### 实施建议与默认内容

以下为依据现有实现选择的实施方式及待审阅内容，不作为用户已选定的个人训练安排。

- **少量完整候选**：预置三分化推类训练／拉类训练／腿部训练，四分化胸部与三头／背部与二头／腿部／肩部与腹部，五分化胸部／背部／腿部／肩部／手臂；候选中明确腹部及其他附加动作所在训练项。部位预览从实际候选内容生成，不用分化名称代替动作覆盖事实。已有其他 N 分化保持可用，自由配置放入调整计划的次级高级入口。
- **动作数量和组数选项**：起步提供每次三、四、五个训练动作及每动作二、三、四组，预选四个动作、每动作四组；选择后先对整轮应用，再允许调整单个训练日。动作及次数／秒数要求沿用对应动作含义，不把全部动作统一为同一种计量，也不把拉伸混入力量训练总组数。
- **候选人工编排**：为每种分化提供固定器械与绳索为主、哑铃与训练凳为主、混合器械等完整候选。候选定义保存每个训练项的有序动作和可增补动作，按目标数量生成实际计划；不能随机按肌肉凑数、复制同动作补足数量，或为了数量宣称没有直接安排的部位已获得独立训练。
- **客观比较直接来自结果**：候选卡展示一轮训练项、主要部位与辅助参与、器械清单、动作组成及每项总组数。数量变化后重新计算实际内容；不使用“初级／高级”“更有效”等效果排名，不给缺乏依据的精确时长。未登记健身房时显示条件，登记后按现有 exerciseAvailable 规则筛选；无法满足时明确说明。
- **生成与保存复用现有业务结构**：共享逻辑把候选及参数转为普通 Program 和各项 Plan，使用现有业务校验、本地事务和同步接口保存，不建立另一种训练记录格式，不预先增加数据库字段或后端接口。所有计划预览完成后才确认写入；取消不改现有资料。候选结果保存后仍可由原开放接口、助手和导入导出读取或调整。
- **明确当前选择**：本机保存当前方案及必要的逐日计划选择，页面切换、主题切换和重新进入不重置。已有单一方案直接沿用；多个方案或同一项有多份计划时允许明确选择，不用修订号或标识字符串推断用户偏好。新整套方案生成一份对应各分化项的无日期计划，预览确认后切换当前选择，不删除旧方案或历史。
- **无日期计划循环**：首页对绑定分化的无日期计划按 nextSlot 结果选择，不再因为曾完成过该计划就永久排除。每次训练产生新的 Session，保留开始时内容；完成、休息、取消和单项调整继续使用原有轮换含义。指定日期及独立计划保持原有非自动循环含义。未来预览展示后续训练项，不凭空添加训练日期。
- **三个主页面与辅助菜单**：开始训练展示下一项、关键要求、未来预览及一个主要开始按钮；调整计划展示当前整套方案、训练量及按日调整；运动记录展示真实完成历史。菜单提供设置、健身房和教程，辅助页面返回后恢复原主页面。移除无调用的独立 CatalogScreen，复用 ExercisePicker、ExerciseDetail 和现有器械教学，不保留另一套教学页面。
- **教程不阻断已有使用**：全新且未完成引导的用户看到短教程，依次了解主要功能、可稍后完成的后端连接、方案选择及提醒条件。已有连接或计划的升级用户不强制重新配置，可以从菜单查看；进行中的训练不被教程打断。后端步骤只展示地址、token 及保存或稍后操作，复用既有保存同步能力，不把完整设置页面的其他选择带入起步流程。说明包含手机可访问的地址、唯一 token 来源、保存同步与离线的区别，不展示真实凭据。系统权限在实际使用时按既有机制申请，不在介绍时批量申请。
- **本机偏好不进入业务备份**：教程完成状态、外观及当前界面选择保存为本机偏好，连接仍使用现有 ConnectionVault；不把 token、主题或教程状态塞入训练计划和导出包。
- **完整主题而非背景变黑**：使用 Material 3 语义颜色，默认跟随系统，允许固定浅色或深色。主要页面、菜单、表单、弹窗、提示及系统栏共同适配；调整状态栏图标可读性，保留肌肉强调色的辨识度。教学图片和照片保持原图，不执行反色。切换通过同一应用状态生效，不重置正在编辑或训练的内容。

相比继续展开全部自由表单，候选先行减少起步决策；相比每个训练日分别必选，优先选择整轮计划符合用户已经明确的方式。高级调整复用既有能力，不为其建立第二套编辑和保存逻辑。

## Risks / Trade-offs

- [候选不符合现场器械] → 候选明确列出真实要求，未选健身房不假装可用；已选健身房复用实际筛选，允许按日及单动作替换。
- [三动作候选被说明为覆盖所有细分肌肉] → 展示实际主要和辅助参与，不隐藏缺少的直接训练，不将更多动作或更多组数当作效果保证。
- [升级误改真实方案与轮换] → 不自动生成或覆盖已有资料，不改变运行中 Session；保留自定义 N，按真实完成记录确定下一项。
- [深色模式只适配部分页面] → 在真实操作中逐项检查主页面、编辑器、教学、系统栏及弹窗，原图不反色；休息期间切换外观验证截止时间不变。
- [验证污染用户生产资料] → 使用独立应用标识及独立数据的实际客户端验证，必要时连接独立真实后端；不清除或写入当前生产应用。验证不是 mock，不把验证训练混入个人历史。

## Migration Plan

1. 增加候选定义、共享生成规则及本机偏好，不改变现有业务文档结构；核验已有任意 N、日期计划与原始单位仍可读取。
2. 将主要起步入口切换到候选引导，修改无日期计划的循环选择，保留已有具体计划编辑供按日调整。
3. 收拢导航和教学入口，接入可重看教程及统一主题，保留原有后端、通知、备份和应用更新功能。
4. 使用独立应用标识在真实设备验证完整配置、训练、循环、调整、教学、教程和深浅色切换；已有生产手机数据和服务保持不变。
5. 验收后沿用既有标签发布与用户手动部署流程。当前方案记录阶段不构建、不发布、不安装新版本。
