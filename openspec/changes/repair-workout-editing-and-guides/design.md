# Design

## Context

参见 proposal.md。WorkoutScreen 当前没有直接更换入口，SessionAdjustScreen 与 replaceSessionExercise 已实现剩余动作替换；零完成组时移除旧条目，但共享校验又要求旧条目存在，两者冲突。历史编辑只能改读数和备注。新重量从 Exercise.loadMode 派生，bodyweight 进入只允许 external/assistance 的 Load.mode 后保存失败。

生产只读实测：historical-machine-flat-press、historical-lat-pulldown、exercise_dbe341aa 的教学返回404；exercise_9dce2d64 正常返回文字及图片、视频地址。因此不存在所有教学均不可用的证据。静态教学表没有 historical-* 键，部分正式动作也缺映射。当前ADB没有连接设备，不能声称已复现手机媒体播放问题。

## Goals / Non-Goals

Goals：共享校验、训练编辑和历史订正规则一致；复用现有动作选择、组编辑、Room、同步和教学来源能力；对不同失败保持准确原因。

Non-Goals：不改数据库结构，不恢复已暂缓的计划目标重量保护，不自动换算重量，不改生产训练记录，不直接安装或部署。

## Decisions

### 已确认决定与原文

- 用户要求“器械动作需要修复”“训练的校验要改”“发现在线教学在客户端显示不可用”“训练中没办法改动作，需要可以直接改动作”。
- 用户确认选择“区分订正与更换剩余内容”：订正保留已有读数和时间、更改实际动作身份；换练仅影响后续组。两者均不改未来模板。
- 用户此前确认重量“用户记多少就是多少”，不强制区分负重与助力。

### 实现决策

1. Session.snapshot 是开始时计划，Session.items/exercises/results 是实际记录。放开实际条目的动作／器械订正，仍验证结果有对应目标及动作说明、时间一致。不能保留一条会阻止现有零完成组替换的不可变规则。更换剩余内容保留已有结果，复用原有分拆逻辑并覆盖零组、部分完成、全部完成边界。
2. 训练卡片提供两个语义明确的操作；历史编辑提供订正实际动作。选择新动作时不把旧动作的重量自动解释为新动作目标；订正已有事实则保留原读数，由用户编辑。
3. 重量数值／单位是记录本身。所有普通与分段重量入口采用一致的记录构造方式，不把动作loadMode直接当作Load.mode。保留既有数据可读性，避免单独修复一个入口。
4. 器械补全依据现有明确资料：绳索、哑铃等已知类别可补，含糊动作标记未知。既有Session.exercises有独立副本，必须涵盖其显示，不只改seed；迁移不得伪造动作形式、改ID或触碰实际读数。使用现有修订和冲突机制，不直接执行生产SQL。
5. 教学复用现有来源目录与确认关联能力。仅补可靠映射，历史变体不确定时允许用户选明确教学，不伪造关联；将当前nullable结果扩展为能区分未连接、无关联与请求失败的内部结果，保留缓存与媒体独立错误。

### 助手建议与待确认事项

没有新的数据库或部署架构选择。生产安装／部署未授权；实施前如发现某历史动作必须确认具体器械变体，保留该项未知并单独询问，不将近似教学自动映射。

## Risks / Trade-offs

- 旧客户端可能再次提交空器械标签；须验证离线同步、旧快照和重复导入，不建立双套动作身份。
- 订正改变统计部位但不能改变训练组数或触发休息／分化消费。
- 真实教学媒体可能受手机网络影响；接口成功不等于视频播放成功，需实际手机验收。
- 正式Release构建不是生产安装或部署；没有ADB连接时须报告手机验收阻塞，不伪称完成。
