# Proposal

## Why

实际训练误选动作后无法订正，训练中更换动作需要离开训练页面；部分动作的器械条件和在线教学信息不准确。自重动作填写实际重量还会触发错误的负重／助力校验，阻碍记录实际训练。

## What Changes

- 训练页直接提供“订正实际动作”和“更换剩余动作”，已完成组的处理明确区分，不修改未来模板或开始时计划快照。
- 允许修正实际记录的动作及器械身份，保留关联完整性、日期及真实完成时间检查。
- 重量按原始数值与 kg/lb 保存，不要求用户区分负重或助力，修复 bodyweight 被误传入重量模式。
- 修复历史器械动作的误导性条件显示，已知类别使用明确资料，未知保持未知，不按名称猜测动作变体。
- 修复可靠动作与在线教学的关联，并区分无关联、未连接、服务请求失败和媒体失败。
- 更新行为测试、接口文档与正式构建交付。

## Capabilities

### New Capabilities

- `workout-record-correction`: 实际动作订正、训练内更换与原始读数保存。
- `exercise-information-integrity`: 器械条件与在线教学的准确关联及可识别失败状态。

### Modified Capabilities

无已归档主规范；本变更承接 focus-training-workflow 与 define-personal-training-app 的相关要求，并以本变更确认的新规则替代训练调整必须离开训练页的旧规则。

## Impact

涉及 shared 业务校验、Android 训练与历史编辑、教学读取、服务端教学关联和器械资料处理。保留现有 SQLite/Room 文档结构；不进行数据库 schema 变更，不在开发期间改写生产训练记录。计划目标重量清空保护暂缓，生产安装和后端部署需单独授权。
