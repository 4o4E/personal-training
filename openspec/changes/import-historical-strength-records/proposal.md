# Proposal

## Why

用户要求将工作区已有训练数据导入正在运行的个人后端，并确认本次仅导入八次力量训练、98个记录组与反馈，不导入羽毛球。现有实际训练格式强制要求具体时间且每组只有一种重量，无法忠实表示仅有日期的旧记录及一组内降低重量的记录。

## What Changes

- 允许历史力量记录只提供真实已知的日期；缺少的开始、结束和每组完成时间保持未知，不补造时间或时长。实时训练继续记录真实时间。
- 支持在一个实际完成组中保存按顺序发生的多段重量与次数；10月13日的侧平举降重记录仍计为一组。
- 在运动记录、日期筛选、同步、开放接口与完整备份中一致保留历史日期、组内明细、原始 kg/lb、明确记录的单侧配重和反馈。
- 通过现有鉴权业务接口合并导入八次实际力量训练；仅转换真实完成内容，不将计划、下次调整要求或恢复反馈变为完成组。
- 导入前备份当前后端；保留来源、使用稳定标识，重复导入不增加记录，有冲突停止，不自动覆盖。原始 Markdown、现有分化方案、健身房和器械资料保持不变。
- **BREAKING**：新历史记录不能由现有 0.0.2 客户端正确解释；必须先完成新版应用与后端的更新和验证，再向生产写入这批记录。备份的版本与兼容要求必须阻止旧软件误读新格式。

## Capabilities

### New Capabilities

- `historical-strength-records`：仅有日期的历史力量记录、单组多段实际完成明细、原始资料追溯，以及这些记录在展示、分析、同步和备份中的完整保留。

### Modified Capabilities

无。当前主规范清单为空；既有变更中的同接口鉴权、合并导入、原始单位和实际完成统计要求继续适用，本次不重新定义这些能力。

## Impact

- 共享领域格式与规则：`Session`、`SetResult`、历史排序与汇总、实际记录与实时训练的约束。
- 后端：`/v1/history` 日期筛选、既有文档读写和同步、版本化备份的导入导出。继续使用 Ktor、SQLite 与唯一 token，不直接修改生产数据库。
- Android：运动记录及详情、离线数据的解码、备份与同步；适配引用历史时间的现有调用。实时训练、轮换、通知、深色模式与三项导航不改变业务行为。
- 项目级操作 skill、开放接口说明和版本说明；新增本次确定来源的转换步骤，不编写任意 Markdown 格式的通用导入系统。
- 实际来源为 `record/1012.md`、`1013.md`、`1014.md`、`1015.md`、`1019.md`、`1020.md`、`1021.md`、`1026.md`。不导入 `1022.md` 的羽毛球，不访问或迁移小米数据，不操作 Hevy。
- 本文件记录需求与计划，不代表代码已实现、生产已更新或98组记录已经导入。
