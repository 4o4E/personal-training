# Proposal

## Why

用户要求工作区已有力量训练以应用原生记录进入正在运行的后端，并在日历显示训练分类与实际完成组数。仅有日期、原计划缺失及组内降重必须保持真实；Markdown只作为工作区来源，不作为云端记录正文。

## What Changes

- 同一训练模型表达已知日期、未知时间、实际动作与组内多段负重；不补造时间、目标或实际器械。
- 开始训练时保存明确选择的分化名称，历史保存已确认分类；无明确分类显示自由锻炼，不根据当前计划或动作组合反推。
- 日历仅展示日期、简短分类和实际完成组数，详情展示原生动作、各组明细与整理后的反馈。
- 保留原始kg/lb和真实负重含义，未知含义不在每组显示提示，也不被改为猜测值。
- 历史来源只保留来源标识和本地日期，移除Markdown全文；原始文件保留在record/。
- 在既有八条历史文档上带修订号整理分类和反馈，仍为98组，不重复导入，不修改实际结果、方案或素材。
- 新备份格式为3并读取既有1/2/3；先更新正式应用及后端，再整理生产资料。沿用现有签名、包名、token与业务接口。

## Capabilities

### New Capabilities

- `historical-strength-records`：原生历史力量记录、真实日期精度、明确分类、多段实际组及反馈在展示、同步、查询和备份中的一致保留。

### Modified Capabilities

日历遵循`focus-training-workflow`中的真实运动日期与详情入口规则；日期格采用分类与完成组数摘要，不改变通知和轮换业务。

## Impact

- 共享Session、HistoricalSource、负重显示和版本化备份；不修改SQLite或Room表结构。
- Android训练开始时的分类保存、日历与详情；四、五及其他N分化仍使用明确选择的名称。
- 后端既有文档校验、同步与导入导出，以及项目级skill和开放接口说明。
- 固定来源整理步骤仅处理record/1012.md、1013.md、1014.md、1015.md、1019.md、1020.md、1021.md、1026.md；不修改原文件，不导入羽毛球或小米数据，不实现通用Markdown导入系统。
