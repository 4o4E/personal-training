# Spec Delta

## Purpose

让同一版本的安卓应用、后端运行包和容器镜像具有一致的发布来源，通过标签控制正式交付，使用已经发布的运行包构建镜像，保证手机与手动部署服务器都能取得实际可用的产物。

## ADDED Requirements

### Requirement: 标签控制正式发布

系统 MUST 仅在推送受支持的正式版本标签时创建正式 Release 和发布镜像；普通提交与拉取请求 SHALL 执行相关检查，不发布正式产物。显示版本、安装更新使用的内部版本号及运行包版本 MUST 来自同一版本定义。

#### Scenario: 发布新版本标签
- **WHEN** 用户推送合法的正式版本标签
- **THEN** CI 发布对应版本的签名 APK、可直接运行的后端包及应用更新资料，产物版本与标签一致

#### Scenario: 提交尚未发布的修改
- **WHEN** 用户推送普通代码提交或创建拉取请求
- **THEN** CI 检查相关应用和后端修改，但不创建 Release，也不更新正式镜像标签

### Requirement: 正式安装包保持签名身份

正式 APK MUST 沿用当前手机已安装应用的签名身份且关闭调试功能；签名密钥 MUST 保存在受保护的凭据存储，不进入源码、安装包附件或日志。版本增加后 MUST 能覆盖安装并保留训练数据。

#### Scenario: 安装后续正式版本
- **WHEN** 手机已安装使用当前签名的版本，并取得更高内部版本号的正式 APK
- **THEN** 安卓允许覆盖安装，不要求卸载应用，原有计划和实际训练资料保留

### Requirement: 镜像复用实际 Release 产物

镜像 MUST 在 Release 产物就绪后，使用该版本 Release 的后端运行包组装，不能在 Docker 构建中再次执行后端编译。正式镜像 SHALL 同时提供该版本标签和 Compose 使用的 latest 标签，保留依赖、动作素材及业务代码分层。

#### Scenario: 构建正式镜像
- **WHEN** 对应标签的后端运行包已经作为 Release 附件发布
- **THEN** 镜像构建取得该附件并封装到运行环境，实际启动及鉴权检查通过后发布版本标签和 latest

### Requirement: 发布产物公开且训练资料隔离

现有源码仓库、Release 和 GHCR 镜像 MUST 公开，手机和部署端 SHALL 无需 GitHub 登录即可取得发布产物。个人训练记录、小米资料、业务 token、签名私钥及临时验证数据 MUST 不进入源码或公开产物。

#### Scenario: 匿名取得正式产物
- **WHEN** 未登录 GitHub 的客户端下载已发布 APK、后端包或拉取镜像
- **THEN** 请求成功且产物不包含个人训练资料或凭据

### Requirement: 交付使用已经检查的构建结果

同一次正式发布 MUST 复用共享代码构建结果和已检查的应用及后端产物；构建或行为检查失败时 MUST 不继续发布其正式产物。

#### Scenario: 发布前后端行为检查失败
- **WHEN** 正式发布中的后端行为回归失败
- **THEN** 不发布该次运行的正式 APK、后端包或镜像
