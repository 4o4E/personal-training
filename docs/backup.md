# 备份与迁移

## 备份范围

应用设置中的系统 ZIP 选择器提供本机资料包和后端在线完整备份：

- 手机本机导出包含手机资料及已下载的健康数据缓存，不包含后端 token、手机授权/连接配置或设备偏好；公开动作媒体缓存是可重建数据，不作为备份内容或恢复保证，清除缓存或换机后可联网重新下载。
- 后端在线导出包含完整训练业务资料、动作目录/文字资料、用户上传图片及服务器健康数据。不包含从来源网站下载的 SmartWorkout 图片或视频；这些媒体由手机直接下载并仅缓存在手机，可按需重新下载。完整健康备份需在线通过配套后端导出与恢复，不要把手机已缓存范围视为完整健康资料。
- 训练包格式为 v6，读取兼容 v1–v5。旧训练包可离线导入；含完整健康资料的包离线导入会在修改本机资料前拒绝。
- 导入默认合并，不替换已有不同内容；需要替换时必须由用户明确选择。

更换后端时，先从旧后端导出完整资料，再导入目标后端，最后修改手机连接地址。只修改地址不会复制或清空服务器资料。

## 手机更新

升级前分别备份手机资料和后端完整资料。更新后覆盖安装同版应用，不要卸载或清空资料。客户端及配套后端都必须支持对应的备份格式；旧版本可能无法读取或同步新格式资料。

## 服务器备份与回退

服务器持久化目录（容器内 `/data`，宿主机部署目录例如 `training-data/`）同时保存后端资料/token 和采集器状态。升级前备份完整目录；需要回退时还原该备份并使用与其匹配的服务版本。不要把本机 `data/xiaomi/` 私人数据库拿来替换服务器卷。

## 小米采集器私有数据备份

本机采集数据默认位于 `data/xiaomi/`，包括 SQLite、原始响应和凭据。采集器数据库启用 WAL；不要直接复制正在写入的 SQLite 主文件。应在停写后使用 SQLite 在线备份，或确保数据库一致性地包含 WAL，再连同 `data/xiaomi/data/raw/` 与凭据私下备份。仅保留 SQLite 会失去原始响应的回溯和重导能力。

迁移细节见[采集器维护指南](xiaomi-collector-maintenance.md)。
