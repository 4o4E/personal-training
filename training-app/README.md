# 个人训练

Android 原生训练应用、自有 Ktor 后端、SQLite 存储和项目级训练操作 skill。Android 8.0 及以上；不提供 iOS 或浏览器界面，后续浏览器继续遵守只读数据边界。

启动器图标以 `branding/app-icon.svg` 为图形来源；正式版应用名称为“个人训练”，验证版为“个人训练·验证”。

## 手机操作

1. 首次进入可按教程配置后端、通知及定时唤醒权限，或稍后连接后端、处理权限；已有资料的用户可继续使用。升级前保留的本机选择在离线时继续可用；首次成功读取云端后，云端已有安排优先，云端尚无安排时再迁移旧本机选择。离线期间若同一安排又被云端修改，两份内容保留并需从运动记录右上角同步图标打开详情，明确选择冲突。
2. 在「调整计划」配置整轮及当前方案，比较三、四、五分化候选，也可在「全部计划与日期安排」维护自定义 N 分化、独立计划与指定日期安排。页面顶部直接显示下一训练部位和自动轮换状态；点选训练项可手动指定，选择「自动轮换」可恢复按实际完成记录计算。已有计划优先复用；缺少可复用计划的部位，会按已有日期安排或最近同类实际记录补齐并绑定循环模板，保留计划明确目标与原始单位。确认后先保存到本机安排，联网后同步云端；未来日期安排用于对应日期的计划预览，不要求每天另行安排训练。
3. 候选可选力量动作数量与组数，预览动作顺序、部位、器械和目标；可添加拉伸并指定侧别、次数或时长及顺序。确认前可返回修改或取消，不会提前保存。
4. 「开始训练」按 UTC+8 日期直接进入当天唯一训练记录；已有进行中的训练继续执行，否则使用当天准备好的训练计划。无需先确认开始，也无需为每天单独安排训练；上一日仍在进行的训练不会阻挡新一天。当天完成的记录仍可继续编辑和训练，直接继续未完成的目标；只有要超过原定目标时，才明确追加待执行组。首次尚未配置整轮方案时，先从「调整计划」完成初始化；日期在恢复前台及午夜刷新。
5. 修改当前训练时，从「调整计划 → 调整本次剩余内容」进入。替换或加入的仅是未完成动作和拉伸，已完成组及实际读数保留。未来计划编辑只影响之后的训练。
6. 每组记录实际读数后保存并自动休息；整次训练所有有效目标中的最后一组保存后不休息（不是每个动作的最后一组）。同次训练的同一动作后续组默认沿用最近完成组的次数、原始重量与 kg/lb 单位，当前未提交草稿优先，首组仍用计划目标。常用重量可选择或增减，不猜测器械档位；休息时长仍按原计划。修正已完成组不重启计时，导航离开再返回不重置读数或休息截止时间。
   - 次数和重量使用位置一致的紧凑输入框，支持加减与手动输入。拖动按钮必须先成功通过系统长按识别才激活，成功时新增一次系统轻触反馈；激活后的真实跨档调整继续使用原有轻反馈。长按前的滑动不会拦截页面滚动或改变数值。激活后按住上下箭头，在手指旁显示临时竖向刻度；松手或取消后收起，不占用平时的页面高度。
   - 重量右侧菜单提供常用读数与0.5、1、2.5、5、10步长，按动作、器械和原始单位记住本机选择；改变步长不会改变现有数值，手输入小数不会被强制取整，kg/lb不换算。
   - 当前动作蓝色展开，完成动作绿色并带完成标记，其他动作紧凑展示。动作标题下显示计划，实际完成组独立展开；进度沿用连续进度条。切换动作保留各组未提交草稿，完成整项后突出下一个未完成动作；教学、实际记录修改、撤销和复杂分段输入仍可使用。
7. 「运动记录」右上角提供标准Material同步图标：正常时点击同步，进行中显示进度并阻止重复提交；有问题时点击查看原因和重试，长按随时查看详情。一次操作结束只在底部导航上方显示一次短暂Compose提示，导航始终可见、可操作，页面不常驻同步状态。详情保留训练、素材、健康读取、小米采集、待上传与冲突入口；采集期间仅在该页面可见时更新阶段。
   - 点击日历日期，在同一弹窗顶部查看全天健康概览：实际步数、步行距离、活动消耗、静息心率、当天最长的一次主睡眠和最近身体测量。原始采样、睡眠分段及其他身体测量按需展开；只有健康数据的日期也可查看，不标记为完成训练。小米运动摘要只读保留在健康详情，不自动创建或更新用户运动。
   - 每次训练或其他运动在起止时间完整时显示对应时间范围的心率图，标记开始、结束及真实小米运动采样点；只使用 `source=xiaomi_workout` 的 `active` 运动明细，不以日常稀疏采样伪造曲线，间隔超过2.5秒的采样缺口断开、不插值补造，无匹配运动采样时明确说明。图表按用户保存起止筛选，离线继续显示现有健康缓存；跨日或缓存未完整读取时说明范围限制。修改运动起止并保存后按新范围筛选；关联设备的时长、消耗及心率摘要独立展示，不因修改用户时间而重新计算。日历与用户运动列表仅显示用户明确手动录入或明确导入的活动；旧自动投影须同时满足ID以`xiaomi-`开头且`sourceId`以`misports:activities:`开头才排除，不能按来源前缀单独过滤，因此明确导入徒步及手动UUID仍显示。
   - 阅读状态按动作紧凑展示实际组。点击唯一的「修改」后，统一修改重量、kg/lb单位、次数或时长、分段读数、训练反馈，以及其他运动的名称、日期、起止、独立时长、距离和备注。进行中的训练继续在「开始训练」修改；小米原始指标只读。
   - 「取消」放弃全部草稿并返回阅读；「保存」一次写入本机，再同步云端。删除先作为草稿标记，可以撤销；未保存时点击外侧或返回会确认是否放弃。输入无效时保留草稿，不保存部分字段。来源时长与起止区间独立保留，缺失读数和时间不补造。
   - 健康内容先显示已下载缓存，再按日期刷新；未下载不等于没有记录。日历按连续周行上下滚动，范围包含最早健康资料，月底和月初共用周行。日期格约56dp，横纵间距6dp；当前浏览月正常强调，其他月份日期文字与容器底色弱化但仍可点击。每月大号淡色数字属于该月对应的日期区域，与日期一起同速滚动；跨月时各月数字分别进入或离开视野，不固定覆盖屏幕中央。顶部继续显示完整年月。推绿、拉蓝、腿橙、自由灰；今天底色与计划边框保留，未训练计划以虚线区分。
   - 月份数字使用粗体和中性灰阶，当前浏览月份对比更明显，相邻月份更淡。拖动到顶端或底部时，数字与日期一起产生系统拉伸回弹，松手共同恢复，顶部标题和底部导航保持固定。
8. 从左上角菜单进入独立「设置」页面，系统或页面返回均回到原位置；若侧栏打开，系统返回优先关闭侧栏，随后再按页面导航栈返回。设置中的导入/导出使用系统 ZIP 选择器：本机导出只保存手机已有资料和已下载健康缓存；后端在线操作才能导出完整健康备份，恢复时可选择合并或明确替换。旧训练包仍可离线导入；含完整健康资料的包离线导入会在修改本机资料前拒绝。设置还可管理外观、后端连接配置/断开、通知权限及更新；休息中切换设置不会改变计时。通知与定时唤醒权限也可在首次教程配置，未授权时仍可继续完成教程。
9. 健身房和器械可从菜单选填；动作教学可在计划预览、动作选择与训练中查看。

候选保留可对应的最近实际读数，不强制转换 kg / lb。未填写负重不等于零重量；更换具体器械后需要确认该台器械的实际显示。拉伸不套用力量动作的统一组数。

## 编译与安装

使用 JDK 21、Android SDK 36 和 Build Tools 36.0.0，设置好 `JAVA_HOME` 与 `ANDROID_HOME`，并按下文配置正式签名环境变量。所有命令在本目录执行。

Windows 原生命令：

```powershell
.\gradlew.bat :server:test :server:installDist :android:assembleRelease
adb install -r android\build\outputs\apk\release\android-release.apk
```

Linux 后端构建不需要 Android SDK：

```sh
./gradlew -PserverOnly :server:test :server:installDist
```

应用、共享类型和后端分别位于 `android/`、`shared/`、`server/`。Gradle 包装器随项目提供，不需要全局安装 Gradle。

正式签名 APK 与后端 ZIP 可从 [Release](https://github.com/4o4E/personal-training/releases/latest) 下载，无需编译。后端 ZIP 包含 `bin/`、依赖和动作素材，解压后使用 JDK 21 运行 `bin/server`（Linux）或 `bin/server.bat`（Windows）。

正式版本从 `v0.0.1` 开始，标签为 `vMAJOR.MINOR.PATCH`。本地正式构建设置 `ANDROID_KEYSTORE_PATH`、`ANDROID_KEYSTORE_PASSWORD`、`ANDROID_KEY_ALIAS` 后执行：

```powershell
.\gradlew.bat -PreleaseVersion=0.0.6 :server:test :server:distZip :android:assembleRelease
```

内部版本号为 `MAJOR × 1000000 + MINOR × 1000 + PATCH + 1`，次版本与修订号不超过 999。签名必须使用同一份密钥才能覆盖安装；密钥在仓库之外备份，不提交到 Git，CI 使用三个对应的签名 Secrets（密钥文件为 `ANDROID_KEYSTORE_BASE64`）。

## 运行后端

Windows：

```powershell
.\gradlew.bat -PserverOnly :server:installDist
.\server\build\install\server\bin\server.bat
```

Linux：

```sh
./server/build/install/server/bin/server
```

默认监听 `0.0.0.0:8080`，资料位于当前运行目录的 `data/`，与已有运动记录及小米数据库完全独立。

| 环境变量 | 用途 |
|---|---|
| `TRAINING_DATA` | 自有训练数据库、上传图片和服务器 token 的持久目录，默认 `data` |
| `TRAINING_HOST` | 监听地址，默认 `0.0.0.0` |
| `PORT` | HTTP 端口，默认 `8080` |
| `TRAINING_TOKEN` | 可选的唯一 token；不提供时自动生成并保存在 `data/token`，提供空值则启动失败 |

在首次教程或「左上角菜单 → 设置」填写手机实际能够访问的后端地址及 token，点击保存并同步。不要填写服务器自己的 `localhost`；调试中的 ADB 端口转发不等同于长期可用的网络部署。公网使用 HTTPS 反向代理，不通过日志或聊天发送 token。

仅本机验证时可以把 `TRAINING_HOST` 设为 `127.0.0.1`。离线训练不要求后端运行；手机保存的待同步记录会在连接恢复后上传。后端只能读取已经上传的数据。

## CI 镜像发布与手动部署

源码、GitHub Release 与 GHCR 镜像均公开，工作流位于根目录 `.github/workflows/publish-training-image.yml`。默认分支提交及拉取请求检查 Android、后端与采集器；采集器 Release 仅从源码树 `training-app/collector/collector/` 选择 `__init__.py`、`__main__.py`、`cli.py`、`config.py`、`service.py`、`source.py`、`state.py` 与运行依赖，ZIP 中模块位于 `collector/`。源依赖只白名单打包 `misports/milib`、`schema.sql` 和 `requirements.txt`。不读取或打包 `misports/data`、`raw`、凭据、cookie、record 或个人说明。推送 `vMAJOR.MINOR.PATCH` 标签才正式发布，普通提交不创建 Release 或更新镜像。

同一标签生成签名 APK、后端 ZIP、采集器 ZIP 和 `update.json`，先保存为 Release 草稿。APK 内部版本号由同一版本计算，必须使用同一签名密钥才能覆盖安装。后端镜像从该版本 Release 后端 ZIP 组装；采集器镜像从该版本采集器 ZIP 组装，两者均不在 Docker 阶段重新编译。镜像启动、鉴权和部署配置检查通过后发布版本标签和 `latest`，匿名拉取验证通过后才公开正式 Release 和应用更新。

### 镜像访问

公开镜像为 `ghcr.io/4o4e/personal-training:latest` 与 `ghcr.io/4o4e/personal-training-collector:latest`，指定版本分别使用 `v0.0.6` 等标签。APK、更新资料、后端 ZIP、采集器 ZIP 及镜像均无需登录 GitHub 即可下载或拉取。

公开采集器制品只含程序与依赖；源SQLite副本、小米账号凭据、采集状态/原始响应及训练资料均由部署端私有配置。采集器只访问后端内部鉴权接口。

### 部署与更新

1. 在服务器建立固定部署目录并复制 `training-app/compose.yml`；创建私有 `training-data/` 目录，确保容器运行用户 `10001:10001` 可读写。该宿主目录同时持久保存后端资料/token和采集器私有状态。
2. 首次接入时，在执行Compose前将工作区 `misports.db` 的一致性副本放入 `training-data/misports.db`；不要直接复制正在写入的数据库。后续迁移不需要把源库放进公开包。
3. 运行 `docker compose up -d training` 启动后端；未配置显式 `TRAINING_TOKEN` 时后端会在 `/data/token` 生成并持久保存 token。Compose 会将主机显式设置的 `TRAINING_TOKEN` 同时传给后端和采集器，并优先采用该值；未设置时采集器读取共享私有目录的 `/data/token` 文件。
4. 下载同版公开镜像并先做现有历史的首推：

```sh
docker compose pull
docker compose run --rm --no-deps --entrypoint python collector -m collector publish
```

`publish` 从私有源库的一致性副本读取历史并提交到后端，不登录小米云；如网络或后端提交失败，已确认批次进度保留，可再次执行 `publish` 续传。运动心率回填独立于日常心率水位，每轮自动按最多100个活动分批遍历现有活动并逐批提交；分批断点保存在采集器私有状态中，失败后重试可续传。仅真实 `hr>0` 采样会进入现有心率数据集，稳定运动来源键确保幂等；不修改源库、既有健康/训练记录或SQLite表结构。
5. 首推完成后创建 `training-data/collector/source/`，将小米账号凭据放入该目录的 `credentials.json`（字段 `user_id`、`pass_token`）或 `cookie.txt`（完整 `userId=...; passToken=...` cookie），限制文件和目录读取权限。采集器登录后会把轮换凭据写回同目录。不得将凭据写入Compose、Git、日志或公开制品。
配置凭据后、启动常驻服务前，可手动运行真实采集并完成运动心率首推：

```sh
docker compose run --rm --no-deps --entrypoint python collector -m collector run
```

这次 `run` 会登录小米、下载尚未获取的运动 FDS 明细，并在同一运行中按有界批次优先提交最新运动，再完成历史活动回填；断网或进程中断时已确认上传及回填断点均保留，下次运行自动续传。后续小时运行只处理近期 FDS 完成/迟到的活动及未完成回填，不每小时重扫全历史。执行前确认训练后端和采集器持久目录均已备份。
6. 启动持续采集：

```sh
docker compose up -d collector
```

采集器启动即执行一次真实采集，之后每小时串行运行一次，并每分钟至多轮询一次后端采集请求；`docker compose logs -f collector` 查看阶段结果。单次增量采集可用 `docker compose run --rm --no-deps --entrypoint python collector -m collector run`。手动历史重扫命令为 `docker compose run --rm --no-deps --entrypoint python collector -m collector rescan --from YYYY-MM-DD [--to YYYY-MM-DD]`；重扫完成后按需执行 `publish` 提交暂存批次。服务器持续采集后不要在个人电脑运行自动采集。

完整健康备份由后端在线导出和恢复；本机训练包只包含已下载的健康缓存范围，并在导出时明确标示范围。离线导入完整健康包时不会先修改部分训练资料。

更新前先分别备份手机本机资料和后端私有 `training-data/` 完整目录，并停止写入；更新顺序是先更新后端和采集器，再核对后端能力及旧训练保留，最后覆盖安装同版APK。不要卸载或清空手机资料。需要回退时同时停止新写入、恢复升级前后端完整备份和对应手机备份，再恢复匹配版本的后端/采集器镜像及APK；不能将旧镜像接到已升级的新数据库。发布镜像不表示生产环境已部署。

容器默认仅将后端发布到服务器 `127.0.0.1:8080`，由 HTTPS 反向代理提供手机可访问地址；家庭网络直连时按实际网络修改端口绑定。健康检查地址为 `/health`，根路径不是网页首页。


## 助手操作 skill

从本目录运行：

```powershell
powershell -NoProfile -ExecutionPolicy Bypass -File tools\install-skill.ps1
```

只安装到当前工作区 `.omp/skills/training-assistant`，不访问全局 skill。工程工作流程技能继续使用工作区已经安装的 `4o4E/skills#feat/openspec-decisions` 和官方 OpenSpec 集成。

操作工具只需要 Python 3 标准库。为助手进程配置 `TRAINING_URL`，以及 `TRAINING_TOKEN` 或 `TRAINING_TOKEN_FILE`；服务器本地可以让 `TRAINING_TOKEN_FILE` 指向持久目录中的 `token` 文件，无需将其内容写入脚本。

```powershell
python skills\training-assistant\scripts\training.py list gym
python skills\training-assistant\scripts\training.py list program
python skills\training-assistant\scripts\training.py history --from 2026-10-01 --to 2026-10-31
python skills\training-assistant\scripts\training.py export training-backup.zip
```

## 备份与迁移

完整 ZIP 备份使用格式 v6，并可读取 v1–v5；数据包含训练、计划、自定义运动及素材，后端完整备份另以独立清单和分流记录承载七类健康资料。备份不包含后端 token、手机授权或连接配置，也不包含教程与外观等设备偏好。训练记录按日期合并为唯一记录，既有记录的来源保留在同日记录中。

设置的系统ZIP选择器区分本机资料包与后端在线完整包：本机导出只包含已下载健康缓存；旧训练包仍可离线导入，完整健康包离线时会在修改本机资料前拒绝。完整后端资料须在线经后端导出与恢复；导入默认合并，已有不同内容不自动替换，确需替换时须由用户明确选择。
迁移到另一套后端时先导出后端完整资料，再导入目标后端，最后修改手机连接；不要把已缓存健康范围视为完整健康资料。

本次业务/备份格式为 v6，兼容读取 v1–v5；要求客户端及配套后端都升级至兼容版本。生产升级前分别保留后端完整资料和手机本机资料备份，先更新后端及采集器并核对格式与原训练，再覆盖安装同版应用。不卸载或清空资料；旧版本不能继续读取或同步使用 v6 资料。

## 提醒条件

休息与拉伸计时由前台服务按持久化截止时间持续运行；倒计时期间保持 CPU 唤醒但不点亮屏幕。整次训练所有有效目标中的最后一组保存后不再开始休息；其余组到时默认只启动持续振动，不播放声音。用户选择铃声后才播放循环声音，并使用系统媒体音量；勿扰与声音可用性遵循系统音频策略。用户可在应用或通知中停止提醒；停止提醒不结束额外休息。拉伸到时显示计时结束，不转为额外休息。结束休息、完成下一组或结束训练时，旧提醒会清除或由新计时替换。

额外休息阶段释放 CPU 唤醒锁；熄屏不逐秒刷新通知，亮屏后从原截止时间恢复显示。计时依赖本机状态，不要求连接后端；到时不会自动记为完成一组。应用被强行停止或手机重启后的自动恢复不属于当前计时支持范围。

通知授权影响系统通知能否显示；精确定时权限用于系统唤醒能力。首次教程分别说明并提供相应配置入口，用户可暂不授权继续使用。实际触发休息或拉伸计时而缺少当前系统所需权限时，应用以情境对话框解释受影响能力，并允许前往系统设置或继续训练；继续后不保证系统未授权的通知或唤醒能力可用。训练页不常驻显示权限缺失警告。铃声使用系统媒体音量，勿扰遵循系统音频策略；提醒声音默认关闭，不启动闹钟应用或全屏提醒。Android 13 的一加 9R 使用普通通知；Android API 36 及以上可请求 Live Updates。OxygenOS 还需在应用通知设置中开启「流体云显示实时活动」，可从应用设置的「实时活动显示设置」进入；普通通知授权不能替代此项。
